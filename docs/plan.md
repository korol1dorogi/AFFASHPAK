## Как выигрываем у команд с большим ИИ-бюджетом
Объём кода нас не спасёт: у них его будет больше. Выигрываем тем, что ИИ за людей не делает.
1. **Соблюдаем ограничения кейса буквально.** Команды с мощными агентами массово теряют баллы на одном и том же: GPT или Claude в продукте вместо моделей с открытыми весами, запуск только с платным ключом, уведомления по email, нет THIRD_PARTY_NOTICES, Docker не поднимается из чистого клона. У нас — чек-лист соответствия (ниже) и независимая проверка на чистой машине (S10).
2. **Целостность важнее широты.** Одна стейт-машина, общая для клиента и банка. Данные вводятся один раз и переиспользуются. Нагенерированные экраны, которые не стыкуются друг с другом, жюри видит сразу — это критерии 01 и 04.
3. **Исследование с явным методом.** 8 синтетических интервью по открытому методу (docs/research/), честно названных синтетикой; кейс оставляет выбор метода команде, но требует связь «потребности → сценарии → решение». Живое интервью, если успеем, — плюс.
4. **Объяснимость и небинарные исходы.** Причины решения в цифрах, контроффер по DSCR, запрос информации, ручное рассмотрение.
5. **Enterprise, который видно:** журнал аудита, идемпотентность, живая демонстрация сбоя симулятора с уходом заявки на ручное рассмотрение, роли, тесты, коллекция запросов, которая прогоняется в CI.
6. **Отточенное демо:** персоны, сброс демо-данных, видео-дубль, отрепетированные ответы на вопросы.

## Продукт

### Карта сайта
**Публичное**
- `/` — лендинг на один экран: что это, кнопка «Войти», демо-учётки на стенде
- `/login`, `/register` — без подтверждения по почте

**Кабинет предпринимателя**
- `/app` — главная: активные заявки, «что дальше», уведомления, ключевые метрики с пояснениями
- `/app/company` — профиль: ИНН → автозаполнение из ЕГРЮЛ/ЕГРИП, сотрудники и роли (бухгалтер готовит, директор подписывает), подключение счёта (демо)
- `/app/match` — подбор «Что вам нужно?»: потребность → продукт → сумма с обоснованием, калькулятор
- `/app/products` — каталог продуктов
- `/app/applications` — список заявок
- `/app/applications/new` — мастер заявки: параметры → данные о бизнесе (предзаполнены) → документы → проверка и отправка
- `/app/applications/:id` — таймлайн статуса, «что дальше», запросы банка, решение с причинами, оффер или контроффер
- `/app/applications/:id/sign` — подписание: код показывается на экране
- `/app/notifications`
- ассистент — выдвижная панель на всех страницах

**Рабочее место банка**
- `/bank` — очередь: фильтры по статусу, продукту, грейду, времени в статусе и исполнителю; счётчики
- `/bank/applications/:id` — вкладки: Заявка, Клиент, Проверки (ЕГРЮЛ, «Прозрачный бизнес», БКИ, счёт), Скоринг (разложение по факторам), Документы, Журнал; панель действий
- `/bank/dashboard` — воронка конвейера, время в статусах, доля автоматических решений
- `/bank/demo` — только на стенде: переключатели сбоев симуляторов, сброс демо-данных, быстрый вход за персону

**Системное:** `/api/docs` (Swagger), `/api/health`, `/admin` — техническая админка, не для демо.

### Ключевые сценарии (каждый — e2e-тест и шаг демо)
1. Кофейня: подбор → овердрафт → автоматический оффер → подписание → выдача.
2. Поставщик: факторинг под отгрузку.
3. Сезонный магазин: просит 5,3 млн → контроффер 2 009 314 ₽ по DSCR → принимает → выдача.
4. Производство: просрочка в БКИ → грейд C → ручное рассмотрение → запрос документа → загрузка → одобрение.
5. Зависимый поставщик: отказ с пояснением «что улучшить».
6. Компания в ликвидации: стоп-фактор, мгновенный отказ.
7. Сбой БКИ: заявка уходит на ручное рассмотрение с пометкой о недоступности источника.
8. Оборудование без залога: просит инвест-кредит → банк предлагает другой продукт — лизинг (исход «другой продукт», F9, D15).

### Синтетические данные
Единый генератор — источник правды и для симуляторов, и для seed. Всё детерминировано по зерну.
- Компании: 200+ ИП и ООО; ИНН и ОГРН с валидной контрольной суммой и кодом региона 00.
- Люди: директора, бухгалтеры, учредители.
- Счета: выписки за 18 месяцев с сезонностью, концентрацией на плательщиках и категориями операций.
- БКИ: обязательства и просрочки. ЕГРЮЛ: статусы, ОКВЭД, адреса. «Прозрачный бизнес»: признаки массового адреса или руководителя, налоговая задолженность.
- Заявки: 200+ во всех статусах — чтобы очередь банка выглядела живой.
- Продукты: каталог с параметрами. Документы: PDF-заглушки с водяным знаком «ДЕМО».
- Проверка генератора: распределение грейдов похоже на правду (A ~15%, B ~30%, C ~25%, D ~15%, E ~10%, стоп-факторы ~5%); персоны воспроизводят числа из [knowledge/credit.md](knowledge/credit.md).

### Дизайн
- Своё название продукта и своя палитра. Логотипы и фирменные шрифты Альфы не используем: правила разрешают чужие материалы только как иллюстрации с указанием источника.
- Шрифты — открытые (Inter или Manrope), иконки — Lucide; всё это — в THIRD_PARTY_NOTICES.
- Уходим от дефолтного вида shadcn: дизайн-токены, шкала типографики, свои ключевые компоненты — StatusTimeline, ReasonList, ScoreBreakdown, MoneyInput, Stepper.
- Тексты интерфейса — простым языком для человека без банковской экспертизы. У каждого статуса и каждой причины есть «что это значит» и «что дальше».
- Пустые, загрузочные и ошибочные состояния; базовая доступность (контраст, клавиатура). Desktop first.

### Инфраструктура
- Compose по умолчанию: db, redis, backend, worker, frontend за Caddy, simulators, swagger-ui, init-контейнер (миграции + seed). Плюс профиль llm (Ollama) и dev-режим.
- Стенд: VPS 3 ядра / 3 ГБ, Ubuntu 26.04, Caddy с HTTPS, домен или бесплатный DuckDNS; swap, ротация логов, внешний пинг (UptimeRobot). Деплой — [deploy.md](deploy.md).
- LLM на стенде: API провайдера с open-weight моделью, лимит бюджета и троттлинг. В репозитории по умолчанию mock.
- CI: lint, тесты, валидация контракта, e2e, коллекция через newman, gitleaks, check --deploy.

## Как выжать максимум из агентов
Контракт и AGENTS.md — главная защита от расхождений: агенты пяти человек пишут под один и тот же контракт.
- Каждому — по одной задаче за раз и маленькие PR. Чем меньше дифф, тем быстрее ревью и тем реже конфликты.
- Документация генерируется из кода: OpenAPI проверяется тестами, коллекция прогоняется в CI, ER-диаграмма строится из моделей. Люди только вычитывают — так документация не врёт.
- Лид в Claude Code держит ядро, ревью и интеграцию. Ревью — узкое место недели, поэтому фичи с фронта лид себе не берёт.

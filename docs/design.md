# Дизайн: требования

Владелец — B1 (дизайн-система), остальные берут всё отсюда и из `/dev/ui`. Маршруты и экраны — [frontend.md](frontend.md).

## 1. Бренд
- **Стиль дизайн-бука Альфа-Банка, своё название (D26, отменяет прежнее правило «не красный»).** Кнопки — компонент открытой дизайн-системы [core-components](https://core-ds.github.io/core-components/) (MIT), палитра, радиусы и шрифт — из её токенов. Логотип и закрытый фирменный шрифт банка не используем; источник указан в THIRD_PARTY_NOTICES.
- Название — **«Оборот»** (выбрал лид; константа `PRODUCT_NAME` в `src/texts/`). Требования, по которым выбирали: по-русски, коротко, без слов «Альфа» и «банк», про опору для бизнеса, а не про «быстрые деньги» (pitch.md, «Не говорить»).
- Палитра дизайн-бука: акцент — красный `#EF3124` (одна красная кнопка на экран, в списках — серые), фон страницы `#F2F3F5`, карточки белые без рамки, радиусы 8 / 12 / 16 / 24, поля — серая заливка внутри карточки и белые с тонкой рамкой на сером фоне. Цвета текста, у которых в дизайн-буке контраст ниже 4,5:1, затемнены до AA (`--primary-ink`, статусы). Значения — в `src/index.css`. Тема только светлая: компоненты дизайн-бука поставляются в светлой теме, как и веб-кабинет банка для бизнеса.
- Тон: спокойный и деловой. Никаких «Поздравляем!!!» и «Деньги за секунды».

## 2. Токены (`src/index.css`, CSS-переменные + Tailwind `@theme`)
| Группа | Что задать |
|---|---|
| Цвет — основа | `background`, `foreground`, `card`, `muted`, `border`, `input`, `ring`, `primary` (+ `-foreground`) |
| Цвет — смысл | группы статусов `status-action`, `status-progress`, `status-success`, `status-danger`, `status-neutral` — каждая со светлым фоном `-soft` для плашек; плюс `paper`, `surface`, `sunken`, `ink`, `ink-muted`, `line`, `primary-soft`, `brass` (имена shadcn — `background`, `card`, `muted`… — оставлены как синонимы) |
| Цвет — статусы | группы, не отдельные статусы (таблица ниже) |
| Типографика | системный шрифт (`system-ui`, как `--font-family-system` дизайн-бука: фирменный шрифт закрытый); шкала 12 / 14 / 16 / 20 / 24 / 32; веса 400 / 500 / 600 / 700; цифры в таблицах и суммах — `tabular-nums` |
| Отступы | сетка 4 px; внутри карточки 16–24, между блоками 24–32 |
| Радиусы, тени | радиусы 6 / 10 / 16 px (`sm` / `md` / `lg`); тени только у всплывающих элементов (диалог, панель ассистента, меню) |
| Иконки | Lucide (уже в проекте), 16 и 20 px, всегда с текстом или `aria-label` |

Контраст текста и фона — не ниже 4,5:1 (WCAG AA), у крупного текста — 3:1. Проверить для всех пар токенов и показать в `/dev/ui`.

### Статусы → цветовые группы
| Группа | Статусы | Цвет | Иконка |
|---|---|---|---|
| Нужно действие клиента | `draft`, `info_requested`, `offer`, `signing` | `status-action` | `CircleAlert` / `PenLine` |
| В работе у банка | `submitted`, `processing`, `manual_review` | `status-progress` | `Clock` |
| Успех | `signed`, `issued` | `status-success` | `CircleCheck` |
| Отказ | `declined` | `status-danger` | `CircleX` |
| Закрыта клиентом | `cancelled` | `status-neutral` | `CircleSlash` |

Статус никогда не передаётся только цветом: всегда иконка + текст.

## 3. Компоненты дизайн-системы (`src/components/`, B1)
Интерфейсы ниже фиксируем сейчас, чтобы C и B писали экраны параллельно с B1. Типы — из `Schemas` (`src/api/client.ts`).

| Компонент | Пропсы | Что делает |
|---|---|---|
| `StatusBadge` | `status: ApplicationStatus`, `size?: "sm" \| "md"` | цвет группы, иконка, подпись из `texts/` |
| `NextStep` | `status`, `actions: ApplicationAction[]`, `onAction(action)` | «что это значит / что дальше» + главная кнопка |
| `StatusTimeline` | `events: ApplicationEvent[]`, `showInternal?: boolean` | вертикальная лента: время, кто (клиент / банк / система), что произошло |
| `ReasonList` | `reasons: Reason[]`, `variant: "client" \| "bank"` | строка на причину: ✓ / ✗, название метрики, значение против порога, текст; для клиента — простым языком, для банка — с числами |
| `ImprovementList` | `items: string[]` | «Что можно улучшить» после отказа или контроффера |
| `ScoreBreakdown` | `score: Score` | грейд крупно, итог баллов, факторы с баллами и полосой «из максимума» |
| `OfferCard` | `offer: Offer`, `actions`, `onAccept`, `onDecline` | условия; «вы просили N» при контроффере; пометка «другой продукт» |
| `MoneyText` / `RateText` | `value: string` | `2 009 314 ₽` / `24 %`, `tabular-nums` |
| `MoneyInput` | как input react-hook-form; значение — строка `"900000.00"` | разряды при вводе, только цифры, без float |
| `Stepper` | `steps: {key, label}[]`, `current` | шаги мастера, пройденные кликабельны |
| `PageHeader` | `title`, `subtitle?`, `actions?` | заголовок страницы |
| `EmptyState` / `ErrorState` | `title`, `text`, `action?` | пустой список, ошибка с «Повторить» |
| `DemoBadge` | — | плашка «демо» для данных симуляторов и `is_demo` |
| `ConfirmDialog` | `title`, `text`, `confirmLabel`, `danger?` | подтверждение необратимых действий |

Примитивы shadcn, которые добавляет B1: `dialog`, `sheet`, `tabs`, `table`, `select`, `input`, `textarea`, `label`, `form`, `checkbox`, `radio-group`, `tooltip`, `skeleton`, `sonner` (тосты), `dropdown-menu`, `separator`, `progress`. Каждый тянет `@radix-ui/*` — это одобренные зависимости из списка лида (раздел 6), они уже установлены в F0. Уже есть: `button`, `card`, `badge`, `input` (+ `Textarea`, `NativeSelect`), `dialog`. Выпадающие списки в F0 — нативный `<select>` в стиле системы (`NativeSelect`): он доступен с клавиатуры без доработок; переходить ли на Radix Select — решает B1.

## 4. Раскладка
- **Desktop first:** макет под 1280 px, работает от 1024 px; мобильная вёрстка не нужна (кейс: только веб, мобильное приложение не допускается).
- **Кабинет клиента:** шапка 56 px (название, колокольчик, ассистент, профиль), меню слева 240 px («Главная», «Подобрать», «Заявки», «Продукты», «Компания»), контент до 1120 px.
- **Банк:** то же меню («Очередь», «Дашборд», «Демо»), контент во всю ширину; таблица плотная, строки 40 px.
- **Ассистент:** панель справа 420 px поверх контента, не сдвигает его.

## 5. Состояния и доступность
- У каждого экрана четыре состояния: загрузка (скелетон той же формы, не спиннер на весь экран), данные, пусто, ошибка. Все — в `/dev/ui`.
- Клавиатура: всё доступно с Tab; видимый фокус (`ring`); Esc закрывает диалоги и панель; фокус возвращается на кнопку, открывшую диалог.
- Поля: видимая подпись, ошибка под полем текстом, `aria-invalid`, `aria-describedby`.
- Смена статуса заявки и тосты — через `aria-live="polite"`.
- Тексты — простым языком: «Не хватает денег до поступлений», а не «Кассовый разрыв (cash_gap)»; термины — с подсказкой (`tooltip`) «что это».

## 6. Зависимости, нужные фронту (одобряет лид вместе с документом)
Установлены в F0: `react-router` (был), `@fontsource/golos-text`, `@fontsource-variable/manrope`, `sonner`, `@radix-ui/react-dialog`, `@radix-ui/react-tabs`, `@radix-ui/react-select`, `@radix-ui/react-label`, `@radix-ui/react-checkbox`, `@radix-ui/react-radio-group`, `@radix-ui/react-tooltip`, `@radix-ui/react-dropdown-menu`, `@radix-ui/react-separator`, `@radix-ui/react-progress`. Точные версии — последние стабильные на момент установки, `save-exact`; всё вносится в THIRD_PARTY_NOTICES (L10). Всё остальное — только через лида.

## 7. Приёмка B1
- `/dev/ui` показывает токены (цвета с контрастом), типографику, все компоненты раздела 3 во всех состояниях и все статусы.
- Основной цвет — красный `#EF3124` из дизайн-бука (D26; прежнее правило «не красный» отменено); название согласовано с лидом.
- `StatusBadge` и `ReasonList` покрыты тестами Vitest на все значения `ApplicationStatus` и на `passed: true / false / value: null`.

# Решения (пересматривает только лид)

«Источник» у решения — интервью, из которых оно выросло ([research.md](research.md)): R01–R08 — синтетические, по карточкам; L01, L02 — живые, ими гипотезы проверены. У технических решений и решений из правил кейса источника в интервью нет.

D1. Правила агентов — только AGENTS.md. CLAUDE.md не создаём (иначе Claude Code перестаёт читать AGENTS.md). Gemini CLI подключён через .gemini/settings.json.
D2. Contract-first: docs/openapi.yaml — источник истины. Фронт генерирует клиент, бэк валидирует ответы по контракту в тестах, Prism — мок для фронта.
D3. Стек: Django + DRF + PostgreSQL, Redis + Celery для конвейера заявки; React + TS + Vite + react-router + shadcn/ui + TanStack Query; Playwright; Postman/newman; Docker Compose; GitHub Actions. Внешние источники (ЕГРЮЛ, «Прозрачный бизнес», БКИ, счёт, подписание, выдача) — отдельный сервис симуляторов.
D4. Аутентификация — сессии + CSRF на одном origin, без JWT и CORS.
D5. Все кредитные расчёты — backend/apps/credit_math, Decimal, тесты на примеры из docs/knowledge/credit.md.
D6. Подбор = потребность → инструмент → размер → reasons. Правила с прозрачными порогами (пороги — параметры продуктов). ML — только если данные кейса позволяют; качество — Gini/ROC-AUC на отложенной выборке. Источник: [R03](research/interviews/R03.md), [R06](research/interviews/R06.md) — сумма и отказ без объяснений; [R01](research/interviews/R01.md) — короткий разрыв закрывают лимитом; [R04](research/interviews/R04.md), [R06](research/interviews/R06.md) — понять шансы до заявки; проверено живыми [L01](research/interviews/L01.md), [L02](research/interviews/L02.md).
D7. В продукте — «предварительная оценка» с причинами; исходы небинарные: оффер, контроффер, ручное рассмотрение, запрос информации, отказ. Сторона банка — своё рабочее место /bank на том же фронте и той же стейт-машине (docs/state-machine.md); Django admin — только техническая админка. Источник: [R03](research/interviews/R03.md), [R06](research/interviews/R06.md) — причины вместо голого «нет»; [R04](research/interviews/R04.md) — спорный случай уходит сотруднику с запросом документа, а не в отказ; проверено живыми [L01](research/interviews/L01.md), [L02](research/interviews/L02.md).
D8. ИИ-ассистент: только модели с открытыми весами (требование кейса) — через OpenAI-совместимый клиент: mock (по умолчанию, без ключа), API провайдера с open-weight моделью на стенде, Ollama (compose-профиль llm). Инструменты поверх сервисного слоя от имени пользователя; отправку подтверждает человек; журнал вызовов. Модель — в THIRD_PARTY_NOTICES.
D9. Данные: кейс данных не даёт — все данные синтетические и формирует команда (O3): единый детерминированный генератор (S2) для симуляторов и seed, всё помечено «демо». Внешние источники — симуляторы (O4). CASE_DATA_DIR оставлен на случай реальных данных, но не используется.
D10. Безопасность — по AGENTS.md. npm: ignore-scripts + npm ci. В CI единственный секрет — DEPLOY_SSH_KEY для автодеплоя (ключ на сервере ограничен одной командой); actions закреплены по SHA, gitleaks, ruff S, check --deploy.
D11. Деплой — автоматически после мержа в main при зелёном CI (джоба deploy → /usr/local/bin/alfa-deploy на VPS, автооткат при падении). VPS: Caddy + docker compose, наружу только 80/443; сервер настраивает лид.
D12. Репозиторий приватный; решение не публикуем — так требуют правила хакатона.
D13. Контракт v1 (L1): одна стейт-машина на клиента и банк; optimistic locking через version (409 version_conflict); идемпотентный submit по Idempotency-Key; фронт рисует действия только по available_actions; уведомления — только в интерфейсе (опрос), без email и SMS. Источник: прежде всего правила кейса (O5); интервью это подтверждают — [R01](research/interviews/R01.md), [R07](research/interviews/R07.md) не доверяют навязанным услугам, [L01](research/interviews/L01.md) первым убрал бы спам-звонки.
D14. Агрегация выписки в снимок (`statement_metrics`) живёт в backend/apps/credit_math/statement.py — одна реализация для генератора S2 и адаптера счёта L4. Округления и раскладка сумм генератора — в apps/demo_data, не в credit_math. Одобрено лидом 20.10 по ревью PR #11.
D15. Исход «другой продукт» (F9) показывает персона 8 `equipment_no_collateral` (данные граничного случая Г7 из decision-model.md: инвест-кредит без залога → лизинг). Персона 4 остаётся сценарием 4. Сценариев теперь 8. Источник: [R04](research/interviews/R04.md) — сравнить кредит с лизингом на одних цифрах; [R07](research/interviews/R07.md) — технику берут в лизинг; проверено живым [L02](research/interviews/L02.md) — «другой вариант вместе с причиной в цифрах».
D16. `Company.registered_at` остаётся обязательным: дата всегда приходит из ЕГРЮЛ, без ЕГРЮЛ компания не создаётся. Граничный случай Г10 (пустая дата) — только вход теста D5, в засев не попадает.
D17. Оффер действует 30 дней, на код подписи — 3 попытки (как в data-spec.md). Засев сдвигает даты заявок на «сегодня − as_of» (L5).
D18. e2e: C10 — сценарий 1 (клиентский путь), S6 — сценарии 2–8. Сгенерированный JSON синтетики в git не коммитим: `seed_demo` строит его детерминированно при запуске.
D19. Подключения «Счёт» и «ЭДО» — `POST /api/company/integrations/{source}/connect` (контракт был, реализован в C3/PR #30): источник — симулятор, приносит снимок по счёту; факт и время подключения — модель `CompanyIntegration` и поле `Company.integrations` (`bank_account`, `edo`: дата или null), чтобы статус был известен после перезагрузки. Засеянные компании со снимком считаются с подключённым счётом. Источник: [R02](research/interviews/R02.md) — финансирование под документ отгрузки в ЭДО; [R04](research/interviews/R04.md), [R05](research/interviews/R05.md) — сбор документов выматывает больше всего; проверено живым [L02](research/interviews/L02.md) — документы собирали 3 месяца.
D20. Короткое название — отдельное поле `Company.short_name` (контракт и модель), `PATCH /api/company` меняет только его; `name` — юридическое название из реестра, не редактируется. Прежние переименования перенесены миграцией в `short_name`, юридические названия восстановлены по реестру.
D21. Тексты интерфейса — только в `frontend/src/texts/` (D8): тексты фич переносятся туда, не живут в папках фич (C3, B5 перенесены).
D22. ИНН проверяется с контрольными цифрами по алгоритму ФНС — на фронте (форма) и на бэке (lookup, создание компании, 400). Синтетические ИНН реестра проходят проверку; пример в контракте заменён на валидный.
D23. Сотрудник попадает в компанию только с согласия: подписант приглашает по логину (`Invitation`), адресат принимает или отклоняет на `/app/company/new`. Прямое добавление (`POST /api/company/members`) убрано — оно позволяло затащить чужого клиента в компанию, даже подписантом, и он уже не мог подключить свою. Приглашение отвечает 201 на любой логин правильного формата: перебором нельзя узнать, есть ли логин, работает ли он в другой компании или это сотрудник банка (review MEM-1, MEM-2; docs/security.md). Источник ролей: [R05](research/interviews/R05.md) — бухгалтер готовит, а подписывает только директор; проверено живым [L02](research/interviews/L02.md).
D24. Нормативы времени (SLA, XP4) — только у статусов, где ход за банком или системой: `submitted` и `processing` — 1 ч, `manual_review` — 24 ч, `signed` — 1 ч; у ходов клиента и финальных статусов норматива нет. Настройка `APPLICATION_SLA_HOURS` (`SLA_HOURS` в .env), без миграций: срок считается от `status_changed_at`. Просрочку считает бэкенд; у фронта своих порогов нет.
D25. Поля, без которых банк не начнёт проверку (продукт, цель, сумма и срок в границах продукта, сумма отгрузки у факторинга), проверяются при `submit` — 400 по полю, заявка остаётся черновиком. После отправки клиент может только догрузить документы и ответить текстом, поэтому пробел в поле, найденный конвейером, гонял заявку по кругу `info_requested → submitted → info_requested` (аудит 22.10). `submit` принимает `version` черновика, который видел подписант (409 при расхождении). Стоп-факторы по анкете — раньше полноты. Предложение сотрудника — в границах продукта (сумма, срок, ставка; 400). Источник: [R04](research/interviews/R04.md) — «повторные запросы документов — это выматывает больше всего»; [R05](research/interviews/R05.md) — разрозненные дозапросы банка.
D26. Интерфейс — в стиле дизайн-бука Альфа-Банка (решение лида 23.10): кнопки — `@alfalab/core-components-button` (MIT) через нашу обёртку `components/ui/button.tsx` с прежним API; палитра, радиусы и системный шрифт — из токенов core-components. Поля ввода — нативные в виде дизайн-бука: поле core-components всегда управляемое и затирает значения `register` из react-hook-form. Название остаётся «Оборот», логотипа банка нет. Тема только светлая. Отменяет правило design.md «основной цвет — не красный».
D27. Кредитная история понятным языком (BKI1, #54): если на решение повлияла кредитная история — прошлая или текущая просрочка, стоп-фактор С4, — карточка решения говорит, что увидел банк (дни и порог), откуда сведения (бюро кредитных историй, запрос с согласия клиента, SRC1) и что делать: узнать свои бюро через Госуслуги, бесплатно получить отчёт, оспорить ошибку в бюро, приложить справку кредитора о погашении. Прошлую просрочку план XP2 не покрывает: её не отменить. Источник: живое [L01](research/interviews/L01.md) — «Что и откуда — никто не знает. Как исправить — никто не знает»; [R04](research/interviews/R04.md) — боится, что всплывёт старая просрочка.
D28. План «Как получить одобрение» при отказе (XP2, #50): при автоматическом отказе по грейду ниже C клиент видит самый короткий набор шагов по факторам балльной карты — целевое значение, где показатель сейчас и сколько баллов даст шаг, — после которых грейд стал бы C или выше. Перебор детерминированный. Плана нет при отказе по стоп-фактору, при решении сотрудника и когда цель недостижима. Источник: [R03](research/interviews/R03.md), [R06](research/interviews/R06.md) — хотят знать, что именно улучшить к следующей заявке; проверено живым [L01](research/interviews/L01.md).
D29. «Что если» под предложением банка (XP1, #49): ползунки суммы и срока, на лету — платёж, DSCR и «пройдут ли такие условия»; расчёт на бэкенде через credit_math (`POST /api/applications/{id}/what-if`), само предложение от расчёта не меняется. Источник: [R03](research/interviews/R03.md) — урезанная сумма без логики; [R04](research/interviews/R04.md) — сравнить варианты на одних цифрах; проверено живым [L02](research/interviews/L02.md) — «важно в сравнении».
D30. Подписание — кодом с экрана в кабинете, без визита в банк и без SMS: одноразовый код из 6 цифр, 10 минут и 3 попытки (D17). Источник: прежде всего правила кейса (O5, O6); интервью это подтверждают — [R07](research/interviews/R07.md) работает с телефона и избегает визитов в банк, живой [L01](research/interviews/L01.md): «потом подписание в банке — ножками топать».

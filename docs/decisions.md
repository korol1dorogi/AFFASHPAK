# Решения (пересматривает только лид)

D1. Правила агентов — только AGENTS.md. CLAUDE.md не создаём (иначе Claude Code перестаёт читать AGENTS.md). Gemini CLI подключён через .gemini/settings.json.
D2. Contract-first: docs/openapi.yaml — источник истины. Фронт генерирует клиент, бэк валидирует ответы по контракту в тестах, Prism — мок для фронта.
D3. Стек: Django + DRF + PostgreSQL; React + TS + Vite + shadcn/ui + TanStack Query; Playwright; Docker Compose; GitHub Actions.
D4. Аутентификация — сессии + CSRF на одном origin, без JWT и CORS.
D5. Все кредитные расчёты — backend/apps/credit_math, Decimal, тесты на примеры из docs/knowledge/credit.md.
D6. Подбор = потребность → инструмент → размер → reasons. Правила с прозрачными порогами (пороги — параметры продуктов). ML — только если данные кейса позволяют; качество — Gini/ROC-AUC на отложенной выборке.
D7. В продукте — «предварительная оценка» с причинами. Сторона банка — бэк-офис на Django admin (если она есть в кейсе).
D8. ИИ-ассистент: OpenAI-совместимый клиент, по умолчанию LLM_PROVIDER=mock; инструменты поверх сервисного слоя от имени пользователя; отправку подтверждает человек; журнал вызовов. Можно ли отправлять данные кейса во внешние LLM — спрашиваем организаторов.
D9. Данные: сначала данные кейса, синтетика — только для пробелов. Мок-интеграции помечены «демо-данные». Реальные данные кейса — вне репозитория (CASE_DATA_DIR), агенты их не читают.
D10. Безопасность — по AGENTS.md. npm: ignore-scripts + npm ci. В CI единственный секрет — DEPLOY_SSH_KEY для автодеплоя (ключ на сервере ограничен одной командой); actions закреплены по SHA, gitleaks, ruff S, check --deploy.
D11. Деплой — автоматически после мержа в main при зелёном CI (джоба deploy → /usr/local/bin/alfa-deploy на VPS, автооткат при падении). VPS: Caddy + docker compose, наружу только 80/443; сервер настраивает лид.
D12. Репозиторий приватный; решение не публикуем — так требуют правила хакатона.

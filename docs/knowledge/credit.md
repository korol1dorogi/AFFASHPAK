# Кредитная теория для агентов

По материалу команды (19.10), сжато и выверено. Пороги и коэффициенты — параметры продуктов в настройках, а не константы в коде; реальные значения берём из кейса.

## Соглашения
- Деньги — Decimal, округление до копеек ROUND_HALF_UP; коэффициенты — Decimal, 4 знака. Никакого float.
- Ставки — годовые, в долях (0.24, а не 24). Месячная ставка аннуитета r = annual_rate / 12. База дней — 365 (параметр).
- Все расчёты — в backend/apps/credit_math/: чистые функции без Django.
- Если метрику нельзя корректно посчитать, функция возвращает None и причину, а не 0.
- Каждая оценка возвращает reasons: метрика, значение, порог, пройдено ли, текст для клиента.

## Карточки

### annuity_payment(principal, annual_rate, months)
A = P·r / (1 − (1+r)^−n); при r = 0: A = P/n.
Пример: 1 000 000 ₽, 24%, 12 мес → 94 559,60 ₽/мес, переплата ≈ 134 715 ₽.
Проверка: прогон графика (проценты = остаток·r, тело = A − проценты) гасит долг: сумма тела = P, последний платёж добирает копеечный остаток.

### dscr(cfads, debt_service)
DSCR = денежный поток для обслуживания долга / платежи по всем долгам (тело + проценты) за тот же период; для заявки — с учётом нового платежа. Порог по умолчанию 1.25.
CFADS по выписке: очищенные поступления − операционные списания (без погашения кредитов и переводов между своими счетами).
Пример: CFADS 300 000 ₽/мес, текущие платежи 50 000, новый платёж 190 000 → 1.25.
Края: debt_service = 0 → None («долга нет»); CFADS ≤ 0 → не проходит.

### max_loan_by_dscr(cfads, current_debt_service, annual_rate, months, min_dscr=1.25)
A_max = cfads/min_dscr − current_debt_service; P_max = A_max · (1 − (1+r)^−n) / r; округлять вниз.
Пример: 300 000/1.25 − 50 000 = 190 000 ₽/мес; при 24% и 12 мес → P_max = 2 009 314 ₽.
Проверка: annuity_payment(P_max) ≤ A_max и dscr ≥ min_dscr после всех округлений. A_max ≤ 0 → кредит не предлагать.

### debt_to_ebitda(debt, ebitda, cash=0)
Финансовый долг (кредиты, займы, лизинг), опционально за вычетом денег, делённый на EBITDA за последние 12 мес. Ориентир для МСБ ≤ 3–4.
Пример: долг 6 000 000, EBITDA 2 400 000 → 2.5; за вычетом денег 600 000 → 2.25.
Края: EBITDA ≤ 0 → None и стоп-фактор (отрицательное значение — не «хорошее»). По одной выписке не считается — нужна отчётность.

### ccc(revenue, cogs, receivables, inventory, payables)
DSO = receivables/revenue·365; DIO = inventory/cogs·365; DPO = payables/cogs·365; CCC = DIO + DSO − DPO. Остатки — средние за период, если есть.
Пример: выручка 36,5 млн/год, себестоимость 29,2 млн, дебиторка 4,5 млн, запасы 2,4 млн, кредиторка 1,6 млн → DSO 45, DIO 30, DPO 20, CCC 55 дней.
Края: cogs = 0 (услуги) → DIO и DPO = None.

### working_capital_need(receivables, inventory, payables)
Дебиторка + запасы − кредиторка; в примере выше 5,3 млн. Это верхняя граница КПО.
Проверка: DSO·revenue/365 + (DIO − DPO)·cogs/365 = 4,5 + 0,8 = 5,3 млн.
Ловушка: CCC·revenue/365 = 5,5 млн — так считать нельзя, DIO и DPO выражены в днях себестоимости.

### overdraft_limit(avg_monthly_cleaned_credit_turnover, alpha)
Лимит = alpha × среднемесячный очищенный кредитовый оборот (без своих переводов, кредитов, возвратов). alpha и срок транша (30–60 дней) — параметры продукта.
Пример: 3 000 000 × 0.3 → 900 000 ₽.

### factoring_advance(invoice_amount, beta)
Финансирование = beta × сумма отгрузки по документу ЭДО; комиссия — параметр продукта.
Пример: 5 000 000 × 0.9 → 4 500 000 ₽. Риск переходит на покупателя — проверяем его.

### expected_loss(pd, lgd, ead)
EL = PD × LGD × EAD; для лимитов EAD = выбрано + CCF × невыбранный остаток. Только для бэк-офиса и только если PD оценивается по данным кейса.
Пример: 0.04 × 0.45 × 2 000 000 = 36 000 ₽; лимит 1 000 000, выбрано 400 000, CCF 0.5 → EAD 700 000.

### counterparty_concentration(top_inflow, total_inflow)
Доля крупнейшего плательщика в поступлениях. Пример: 2,4 млн из 3 млн → 0.8 — флаг риска (порог — параметр).

### revenue_trend(last_3m_avg, same_3m_last_year_avg)
Сравнение год к году — чтобы сезонность не давала ложных тревог. Если истории меньше 15 мес — сравнение с предыдущими 3 мес и пометка.
Пример: 2,4 млн против 3,0 млн → 0.8, падение на 20%.

## Подбор: потребность → инструмент
| need_type | Ситуация | Продукт | Размер | Главные проверки |
|---|---|---|---|---|
| cash_gap | разрыв до 30–60 дней | overdraft | overdraft_limit | оборот, тренд |
| receivable_delay | отгрузили, покупатель платит позже | factoring | factoring_advance | надёжность покупателя, документ в ЭДО |
| working_capital | закупка, сезон | working_capital_loan | ≤ working_capital_need и ≤ max_loan_by_dscr | DSCR, Debt/EBITDA |
| capex | оборудование, транспорт, недвижимость | investment_loan / leasing | max_loan_by_dscr на длинный срок | DSCR на прогнозном потоке, залог |

Порядок: стоп-факторы → фильтр по условиям продуктов → размер → ранжирование по соответствию задаче (срок, возобновляемость, залог) → reasons.
Ассистент определяет need_type за 2–3 вопроса и вызывает подбор; сам ничего не считает.

## Вне продукта — только питч и дорожная карта
PD в реальном времени, графовый и embedding-скоринг, мониторинг ковенант, проактивная реструктуризация, интеграции с 1С, ОФД, маркетплейсами и СПАРК. Если в UI есть кнопка интеграции — на данных пометка «демо-данные».
У ИП обычно нет баланса и отчёта о прибылях: при налоговом учёте бухучёт они вести не обязаны. Источники для ИП — обороты по счёту, декларация, ОФД; для ООО годовая отчётность есть в ГИР БО ФНС.

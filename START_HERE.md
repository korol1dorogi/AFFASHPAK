# Старт для команды

## 1. Подготовка (один раз)
1. Нужны: Git, Docker Desktop, Node из .nvmrc, GitHub с 2FA. На Windows — WSL2: клонируй репозиторий внутрь WSL и запускай агента там же.
2. Склонируй репозиторий и выполни быстрый старт из README.
3. Запускай своего агента в корне репозитория:
   - Codex (ChatGPT) — читает AGENTS.md сам.
   - Gemini CLI — AGENTS.md подключён через .gemini/settings.json. На бесплатном тарифе Google собирает промты и код — включи отказ от сбора (opt-out) по FAQ о приватности Gemini CLI.
   - Grok Build — последняя версия, вход по API-ключу; если поддерживается, отключи загрузку кодовой базы (harness.disable_codebase_upload). Что агент видит в папке — `grok inspect`.
   - Во всех аккаунтах выключи обучение моделей на своих данных.
4. Никакого автопилота (yolo, full-auto): команды с сетью и удалением — только с подтверждением.
5. В .env у тебя только заглушки; ассистент локально работает на LLM_PROVIDER=mock. Реальные ключи и данные кейса в папку репозитория не клади.

## 2. Первая сессия — вставь агенту, подставив имя и задачу
```
Ты — мой ИИ-напарник на хакатоне, работаем в этом репозитории. Я — {ИМЯ}.

1. Прочитай AGENTS.md и всё, на что он ссылается: docs/case.md, docs/domain.md, docs/openapi.yaml, docs/tasks.md, docs/decisions.md, data/SCHEMA.md, а если задача про расчёты, подбор, решение или ассистента — docs/knowledge/credit.md. Перескажи жёсткие правила, правила про деньги и безопасность из AGENTS.md в 10–12 пунктах. Если какого-то файла не видишь — скажи сразу.
2. Проверь окружение по README: git, Docker, Node из .nvmrc. Подними проект и прогони проверки из раздела «Команды» в AGENTS.md. Если что-то падает — покажи ошибку и предложи исправление, но общий код и конфиги не трогай: это к лиду.
3. Найди в docs/tasks.md мои задачи (владелец — {ИМЯ}). Берём {T__} (или первую, у которой закрыты зависимости).
4. До кода — план: какие файлы создашь или изменишь (только в разрешённых папках задачи), какие операции из openapi.yaml используешь, какие тесты добавишь (для эндпоинтов с id — «чужой пользователь получает 404»), как проверишь критерий готовности. Остановись и жди моего «ок».
5. После «ок»: ветка {ID задачи}-{кратко} от свежего main, небольшие коммиты.
6. «Готово» — только когда линт, тесты и e2e зелёные и критерий готовности выполнен. Покажи вывод проверок.
7. PR — по .github/pull_request_template.md. Нет gh или прав — дай готовый текст описания, открою сам.

Всегда:
- Не хватает эндпоинта или поля в openapi.yaml, нужна зависимость, модель или миграция — сам не делай. Остановись и подготовь короткое предложение для лида.
- AGENTS.md, docs/, модели, миграции, frontend/src/api/ и чужие папки не правь.
- Формулы и деньги — только через backend/apps/credit_math/, только Decimal.
- Реальные данные кейса не открывай, секреты не выводи и не коммить.
- Сомневаешься в требовании — спроси меня, не додумывай.
```

## 3. Следующие задачи — одна строка
`Берём T__. Порядок тот же: план → моё «ок» → код → проверки → PR.`

## 4. Правила команды
- Не хватает поля, эндпоинта или зависимости — одно сообщение лиду: что нужно и зачем.
- Блокер дольше 30 минут — пиши лиду, не жди.
- PR маленькие, по одной задаче; ревью и мерж — лид. Перед PR подтяни свежий main.
- Каждый вечер — сквозной сценарий на стенде; сломал — чинишь первым делом утром.
- Синк каждый день 10 минут: сделал / делаю / блокеры.
- Ничего из репозитория и кейса не публикуем и не пересылаем за пределы команды.

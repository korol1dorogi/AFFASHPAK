## Какие метрики считаются
Метрики — из [docs/knowledge/credit.md](../docs/knowledge/credit.md). Чего нельзя посчитать из данных кейса — помечаем «вне продукта» и не показываем.

| Метрика | Из каких полей | Считается? | Комментарий |
|---|---|---|---|
| cleaned_credit_turnover | выписка: поступления без своих переводов, кредитов, возвратов | ? | |
| cfads | выписка: очищенные поступления − операционные списания | ? | |
| debt_service | выписка: платежи по кредитам и лизингу | ? | |
| dscr | cfads, debt_service | ? | |
| debt_to_ebitda | отчётность: долг, EBITDA | ? | по одной выписке не считается |
| ccc, working_capital_need | отчётность: выручка, себестоимость, дебиторка, запасы, кредиторка | ? | |
| counterparty_concentration | выписка: поступления по плательщикам | ? | |
| revenue_trend | выписка или отчётность за 15+ мес | ? | |

## Синтетика
- [sample/](sample/) — небольшой пример, **все строки — демо**, персональных данных нет (ИНН и названия выдуманы).
- `sample/bank_statement_demo.csv` — выписка по счёту (формат условный, до кейса): `date` (YYYY-MM-DD), `direction` (`credit` поступление | `debit` списание), `amount` (рубли, точка-разделитель), `counterparty`, `counterparty_inn` (ИНН плательщика или получателя; пусто у розницы, эквайринга, сотрудников, ФНС и своих счетов — нужен для концентрации на плательщике), `category` (`revenue`, `own_transfer`, `loan`, `refund`, `payroll`, `rent`, `supplier`, `tax`, `loan_payment`), `purpose`. Полная спецификация — docs/data-spec.md.
- После кейса формат синтетики приводим к формату данных кейса; персоны демо — [docs/demo.md](../docs/demo.md).

# «Оборот» — умный кредитный кабинет предпринимателя

Хакатон «Альфа-Будущее» (Альфа-Банк × Changellenge), трек «Умный кредитный кабинет предпринимателя». Репозиторий приватный, решение не публикуем.

## Что это
Кредитный кабинет для малого и микробизнеса и рабочее место сотрудника банка над одной и той же заявкой. Предприниматель говорит, зачем нужны деньги, и получает инструмент — овердрафт, факторинг, кредит на пополнение оборотных средств (КПО), инвестиционный кредит или лизинг — с суммой и объяснением. Дальше он подаёт заявку и получает предварительную оценку: предложение, иные условия, другой продукт, запрос документов или отказ с советами «что улучшить». Подписание — кодом на экране, выдача — без звонков, почты и SMS. Клиент и банк работают в одной заявке на одной стейт-машине ([docs/state-machine.md](docs/state-machine.md)). Все компании и данные синтетические и помечены «демо», внешние источники (ЕГРЮЛ/ЕГРИП, «Прозрачный бизнес», БКИ, выписка по счёту, подписание, выдача) — симуляторы внутри бэкенда.

ИИ-ассистент на модели с открытыми весами пока в разработке и в эту версию не входит (см. [ограничения](#ограничения-и-допущения)).

## 5 минут до первого сценария

### Что нужно
| Что | Подробно |
|---|---|
| Docker | Docker Desktop (Windows, macOS) или Docker Engine с Compose v2 (Linux). Проверка: `docker compose version` |
| Git | любой свежий |
| Память | выделите Docker **не меньше 4 ГБ** ОЗУ. Замер: работающий стек занимает ~0,5 ГБ, сборка образов — ещё ~0,5 ГБ; остальное — запас для виртуальной машины Docker и браузера |
| Диск | **~3 ГБ** свободно: образы ~1,4 ГБ (замер `docker image ls`) + кэш сборки ~1,3 ГБ |
| Windows | только через WSL2: Docker Desktop запущен, в Settings → Resources → WSL integration включена интеграция для вашего дистрибутива (например, Ubuntu). Клонируйте и запускайте **внутри WSL** — в домашней папке (`~/…`), не в `/mnt/c/…`; все команды — в терминале WSL |
| Не нужно | GPU, Python, Node, платные ключи и доступ к системам банка. ИИ по умолчанию — `LLM_PROVIDER=mock`, без сети и ключа |

### Запуск
```sh
git clone <адрес репозитория> oborot && cd oborot
cp .env.example .env
docker compose up -d --build --wait
```
`--wait` вернёт управление, когда все сервисы здоровы. Порядок старта: база → `init` (миграции и засев демо-данных) → Redis → Celery worker → API → Swagger → `web`.

Сколько ждать (замер на одной машине: AMD Ryzen 7 5800X, 16 ГБ, Windows + WSL2 + Docker Desktop, быстрый канал; на машине жюри время подтвердит независимая проверка чистого клона, P8):

| Запуск | Время |
|---|---|
| Первый: сборка образов с пустым кэшем | ~65 с сборка + ~35 с старт ≈ **2 мин** — плюс скачивание базовых образов (`postgres`, `redis`, `swagger-ui`, `python`, `node`, `caddy`), которое зависит от канала |
| Повторный (`docker compose up -d --build --wait` после `docker compose down`) | **~30 с** |

### Как понять, что всё поднялось
| Что открыть | Что увидите |
|---|---|
| http://localhost:8080 | главная «Оборот» с блоком «Попробуйте за демо-компанию» |
| http://localhost:8080/api/ready | `{"status":"ready","components":{"database":"ok","migrations":"ok"}}` |
| http://localhost:8080/api/docs | Swagger UI по контракту [docs/openapi.yaml](docs/openapi.yaml) |
| `docker compose ps` | все сервисы `Up … (healthy)`; `init` завершился и в списке не виден |

Проверка одной командой, как у жюри: `scripts/check-clean-clone.sh` клонирует текущий коммит во временную папку, поднимает стек под своим именем и на портах 18080/18000 (рабочий стек не трогает), ждёт `/api/ready` и проходит сценарий 1 через HTTP — от подбора до выдачи. В конце всё удаляет; `KEEP=1 scripts/check-clean-clone.sh` оставит стек запущенным.

## Если что-то не так
| Симптом | Что сделать |
|---|---|
| `Bind for …:8080 failed: port is already allocated` (или `…:8000`) | порт занят другой программой. В `.env` задайте свободный: `WEB_PORT=8081` (кабинет) и/или `BACKEND_PORT=8001` (API напрямую, добавьте строку). Затем снова `docker compose up -d --build --wait` и откройте `http://localhost:<WEB_PORT>` |
| `Cannot connect to the Docker daemon` / `docker: command not found` в WSL | запустите Docker Desktop и дождитесь «Engine running»; в Settings → Resources → WSL integration включите ваш дистрибутив, нажмите Apply & restart и откройте терминал WSL заново |
| Очень медленная сборка или ошибки доступа к файлам на Windows | репозиторий лежит в `/mnt/c/…`. Склонируйте заново внутрь WSL: `cd ~ && git clone …` |
| Сервис перезапускается, `--wait` падает по таймауту, в логах `Killed` / код 137 | Docker не хватает памяти — дайте не меньше 4 ГБ. Windows + WSL2: в `%UserProfile%\.wslconfig` в секции `[wsl2]` строка `memory=4GB`, затем `wsl --shutdown` в PowerShell и снова запустить Docker Desktop. macOS и Windows без WSL2: Docker Desktop → Settings → Resources |
| Нужно посмотреть, что случилось | `docker compose ps` — статусы; `docker compose logs init` — миграции и засев; `docker compose logs -f backend worker` — API и конвейер заявки |
| Остановить | `docker compose down` — данные в базе сохранятся |
| Вернуть демо к исходному состоянию | основной способ — войдите сотрудником банка, откройте **Демо-панель** (`/bank/demo`) → «Сброс демо-данных» → «Сбросить»: удалит все заявки и уведомления, выключит сбои источников и заново засеет очередь банка; персоны и учётки останутся |
| Начать с полностью пустой базы | `docker compose down -v`, затем `docker compose up -d --build --wait`. ⚠️ `-v` **удаляет базу целиком**; после `up` контейнер `init` засеет демо-данные заново |

## Учётки
Паролей у демо-учёток **нет**: при `DEMO_MODE=1` (так по умолчанию в `docker-compose.yml`) вход — в один клик. На главной http://localhost:8080 (блок «Попробуйте за демо-компанию») или на `/login` нажмите «Войти» напротив персоны — это `POST /api/demo/login`. Сотрудник банка может переключиться на любую персону с Демо-панели (`/bank/demo` → «Быстрый вход за персону»). Чтобы работать за клиента и за банк одновременно, откройте второе окно в режиме инкогнито или другой браузер: у каждой стороны своя сессия.

| Кто | Кнопка «Войти» напротив | Логин | Что делает |
|---|---|---|---|
| Сотрудник банка | «Сотрудник банка (демо)» | `demo_bank` | `/bank`: очередь, карточка заявки, действия, дашборд, Демо-панель. `demo_bank_2` и `demo_bank_3` — исполнители в очереди для фильтра «по исполнителю», входа за них нет |
| Бухгалтер | «Главный бухгалтер: ООО «Дубрава Мебель» (демо)» | `demo_accountant` | готовит заявку и отвечает банку; отправить и подписать не может — это делает директор |
| Клиенты | см. таблицу персон ниже | `demo_<код>` | подписант своей компании |

Своя учётка — `/register`, без почты и SMS. После регистрации компания подключается по ИНН из синтетического реестра, реквизиты подтягиваются сами.

## Сценарий проверки

### Сценарий 1 — от потребности до выдачи (~3 минуты)
**Клиент** (обычное окно):
1. http://localhost:8080 → «Войти» напротив «ИП Лаврова Анна Сергеевна — кофейня «Зерно и пар» (демо)». Откроется кабинет с показателями бизнеса из выписки (демо).
2. «Подобрать по задаче» → «Не хватает денег до поступлений» → «Показать варианты». Первый вариант — овердрафт 900 000 ₽ и причины: лимит от оборота и другие показатели.
3. «Оформить заявку». Мастер «Параметры → О бизнесе → Документы → Проверка и отправка» уже заполнен из подбора: реквизиты и данные компании повторно вводить не нужно, черновик сохраняется сам и переживает перезагрузку страницы.
4. На шаге «Проверка и отправка» поставьте галочку согласия на запрос кредитной истории → «Отправить в банк».
5. Через несколько секунд, без перезагрузки, статус меняется на «Есть предложение»: карточка «Предложение банка» — 900 000 ₽, 12 мес, с пометкой «Предварительная оценка» и причинами.
6. «Принять и подписать» → «Показать код» — код показывается на экране, SMS нет → введите его в «Введите код» → «Подписать».
7. Статус «Договор подписан», затем «Деньги выданы» (выдача — симулятор). Всё, что происходило, — в ленте заявки и в уведомлениях кабинета.

**Банк** (окно инкогнито):
8. http://localhost:8080 → «Войти» напротив «Сотрудник банка (демо)» → `/bank`: очередь со счётчиками по статусам, фильтрами и отметками о просрочке норматива. Кроме вашей заявки там ~30 заявок засеянной популяции.
9. Откройте заявку кофейни («Заявка №…»): вкладки с проверками источников (ЕГРЮЛ, «Прозрачный бизнес», БКИ, выписка — все пройдены), скорингом (92 балла, грейд A), документами и журналом. Решение принято автоматически, поэтому действий у сотрудника нет: они появляются только у заявок «У сотрудника банка» (сценарии 4 и 7).
10. «Дашборд» (`/bank/dashboard`) — воронка, время в статусах, доля автоматических решений.

## Архитектура
Монолит Django + DRF и React SPA на одном origin за Caddy. Контракт API — [docs/openapi.yaml](docs/openapi.yaml): бэкенд проверяет по нему свои ответы в тестах, фронт генерирует из него клиент. После отправки заявки конвейер — проверка полноты → источники параллельно → скоринг → правила решения — и выдача уходят в Celery worker через Redis. Статус меняет только сервис переходов стейт-машины, и это одна заявка для клиента и для банка. Кнопки на экране рисуются только по `available_actions` с сервера. Вход — сессия + CSRF, без JWT и CORS. Диаграммы контекста, контейнеров, модулей и последовательности, а также решения с альтернативами — [docs/architecture.md](docs/architecture.md).

| Сервис `docker-compose.yml` | Что | Версия |
|---|---|---|
| `db` | PostgreSQL | 18.6 |
| `init` | одноразовый: миграции + `seed_demo` (каталог продуктов, 8 персон, сотрудники банка, 30 заявок популяции через настоящий конвейер) | образ бэкенда |
| `redis` | брокер задач Celery, без хранения, 32 МБ | 7.4.2 |
| `worker` | Celery: конвейер заявки и выдача; при старте дозапускает потерянные задачи | Celery 5.5.3 |
| `backend` | API: Python 3.12, Django 6.1, DRF 3.18; порт `127.0.0.1:8000` | Python 3.12.15 |
| `swagger` | Swagger UI по контракту на `/api/docs` | swagger-ui 5.17.14 |
| `web` | Caddy: собранный SPA (React 19, TypeScript strict, Vite, react-router, Tailwind + shadcn/ui, TanStack Query, react-hook-form + zod) + прокси `/api/*`; порт `127.0.0.1:8080` | Caddy 2.11.7, Node 24.22.0 при сборке |
| `mock` (профиль `mock`) | Prism: мок API по контракту для фронта без бэкенда | Prism 5.15.10 |

Все версии закреплены: образы — тегами, Python-пакеты — `backend/requirements*.txt`, npm — `package-lock.json`. Сторонние компоненты и лицензии — [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

**Смоделированные интеграции.** Кейс требует автономности, поэтому ничего не ходит наружу. Ниже — что именно заменено симуляторами; как каждая интеграция будет устроена в продакшене, описано в [docs/assumptions.md](docs/assumptions.md).

| Внешняя система | Чем заменена |
|---|---|
| ЕГРЮЛ/ЕГРИП | синтетический реестр по ИНН: автозаполнение компании и проверка в конвейере |
| «Прозрачный бизнес» ФНС | ответы генератора: массовый адрес, налоговая задолженность |
| Бюро кредитных историй | ответы генератора; согласие клиента на запрос сохраняется по-настоящему |
| Выписка по счёту, ЭДО | синтетическая выписка за 18 месяцев → финансовый снимок компании |
| Сбои источников | флаг на Демо-панели; ретраи, таймаут 2 с и circuit breaker работают в коде |
| Подписание | одноразовый код на экране вместо SMS и ДБО |
| Выдача | симуляция: после подписи деньги помечаются выданными |
| LLM | `mock` без сети; опционально — OpenAI-совместимый API к модели с открытыми весами |

## Конфигурация
Все переменные — в [.env.example](.env.example); `cp .env.example .env` даёт рабочую конфигурацию без правок. Секретов в репозитории нет: в примере только заглушки для локального запуска.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DJANGO_SECRET_KEY` | заглушка для локального запуска | ключ Django; на стенде — свой случайный |
| `DJANGO_DEBUG` | `1` | режим отладки; на стенде `0` |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1` | хосты, на которые отвечает API |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | пусто | только за прокси на другом origin (стенд: `https://домен`) |
| `DJANGO_ADMIN_URL` | `admin/` | путь админки Django |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | `alfa`, `alfa`, заглушка | база в контейнере `db` |
| `POSTGRES_HOST`, `POSTGRES_PORT` | `db`, `5432` | адрес базы для бэкенда |
| `WEB_PORT` | `8080` | порт кабинета на хосте |
| `BACKEND_PORT` | `8000` (нет в примере, задаётся в `docker-compose.yml`) | порт API на хосте — для фронта в режиме разработки, e2e и коллекции |
| `DEMO_MODE` | `1` | демо-персоны, быстрый вход и `/api/demo/*` (Демо-панель); `0` — выключить |
| `SLA_HOURS` | пусто = `submitted=1, processing=1, manual_review=24, signed=1` | норматив в часах по статусам для отметки «просрочено» в очереди банка |
| `LLM_PROVIDER` | `mock` | `mock` — детерминированный, без сети и ключа; `openai` — OpenAI-совместимый API к модели с открытыми весами |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | пусто | только для `LLM_PROVIDER=openai` |
| `LLM_TIMEOUT_SECONDS` | `20` | таймаут одного запроса к LLM |
| `LLM_TURN_BUDGET_SECONDS` | `35` | время на весь ответ ассистента; дальше ход дописывает заглушка с пометкой. Бюджет + один запрос должны укладываться в 60 с gunicorn |
| `LLM_MAX_STEPS` | `4` | сколько раз за ответ модель может обратиться к инструментам |
| `GUARDRAILS_MODE` | `block` | `block` — ответ с выдуманной цифрой или обещанием одобрения перегенерируется, затем заменяется безопасным; `log` — только записать в лог |
| `CASE_DATA_DIR` | `./data/sample` | папка с данными, монтируется только на чтение; по умолчанию синтетика ([data/SCHEMA.md](data/SCHEMA.md)) |

Задано в `docker-compose.yml`, в `.env` менять не нужно: `CELERY_BROKER_URL` (Redis; пусто — конвейер выполняется прямо в запросе), `THROTTLE_LOGIN` и `THROTTLE_ANON` (лимиты запросов, ослаблены для e2e).

### Подключить модель за минуту
Без ключа ассистент работает на детерминированной заглушке. Чтобы включить модель с открытыми весами, впишите в `.env` — например, Cloud.ru Foundation Models (российский провайдер; ключ — в личном кабинете cloud.ru):

```env
LLM_PROVIDER=openai
LLM_BASE_URL=https://foundation-models.api.cloud.ru/v1
LLM_API_KEY=<ключ>
LLM_MODEL=Qwen/Qwen3.6-35B-A3B
```

`docker compose up -d backend`, затем `docker compose exec backend python -m apps.assistant.llm.smoke` — напишет «готово» или что не так. Подробнее — [docs/assistant.md](docs/assistant.md#как-подключить-модель).

## Ограничения и допущения
- **Данные синтетические.** Данных от организаторов нет: компании, люди, выписки, реестры и кредитные истории создаёт детерминированный генератор команды при старте, всё помечено «демо».
- **Внешние источники, подписание и выдача смоделированы** (O4, O6). Таблица выше, подробно и с путём в продакшен — [docs/assumptions.md](docs/assumptions.md).
- **Только внутри продукта** (O5): ни почты, ни SMS, ни мессенджеров. Регистрация без подтверждения, код подписи на экране, уведомления в кабинете.
- **Логика решения упрощена и описана явно**: прозрачная балльная карта и правила с порогами ([docs/decision-model.md](docs/decision-model.md)). Клиент видит предварительную оценку, а не решение банка.
- **LLM — только с открытыми весами** (O8). По умолчанию `LLM_PROVIDER=mock` — без сети, ключа и GPU. Проверяемая версия не зависит от платных ресурсов (O2).
- **ИИ-ассистент в эту версию не входит**: эндпоинты `/api/assistant/*` есть в контракте, но не реализованы ([docs/api.md](docs/api.md)), кнопка ассистента в кабинете — заготовка.
- Только веб, desktop first (O7). Что сознательно не делали — [docs/mvp.md](docs/mvp.md).

## Команде
Онбординг — [START_HERE.md](START_HERE.md), правила для ИИ-агентов — [AGENTS.md](AGENTS.md), задачи — [docs/tasks.md](docs/tasks.md).

- Фронт с горячей перезагрузкой: `cd frontend && npm ci && npm run dev` → http://localhost:5173 (API — бэкенд на `127.0.0.1:8000`).
- Фронт без бэкенда, на моке контракта: `docker compose --profile mock up -d mock` → http://localhost:4010, затем в `frontend/`: `npm run dev:mock`.
- Клиент API из контракта: в `frontend/`: `npm run gen:api`. Миграции: `docker compose run --rm backend python manage.py migrate`.
- После правок кода воркера: `docker compose restart worker` (Celery не перезагружается сам).
- Стенд — [docker-compose.prod.yml](docker-compose.prod.yml) + Caddy (HTTPS), [docs/deploy.md](docs/deploy.md); деплоит CI после мержа в main.

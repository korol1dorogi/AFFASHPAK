# Умный кредитный кабинет предпринимателя

Прототип кредитного кабинета для малого и микробизнеса и рабочего места банка над одной и той же заявкой.

- **Клиент:** вход без почты и SMS → компания по ИНН с данными из реестра (симулятор) → подбор «зачем нужны деньги» → продукт (овердрафт, факторинг, КПО, инвест-кредит, лизинг) с суммой и причинами → мастер заявки → отправка → оффер, контроффер, запрос информации или отказ с причинами → подписание кодом на экране → выдача.
- **Банк** (`/bank`): очередь заявок с фильтрами и счётчиками, карточка заявки, действия сотрудника — одобрить, изменить условия, запросить информацию, отказать.
- **ИИ-ассистент** ведёт клиента по пути (LLM только с открытыми весами; по умолчанию `mock`).

**Что работает сейчас** (21.10): вход, регистрация и демо-персоны; подбор с суммой и причинами; мастер заявки с данными компании и показателями бизнеса; отправка → автоматическая проверка (реестр, «Прозрачный бизнес», БКИ, счёт — симуляторы) → скоринг → оффер, контроффер, другой продукт, запрос данных, ручное рассмотрение или отказ с причинами → подписание кодом на экране → выдача; очередь банка; API карточки и действий сотрудника; флаги сбоя симуляторов (`/api/demo/failures`). **Пока нет:** экранов карточки банка, дашборда и демо-панели, профиля компании, каталога и уведомлений (страницы-заглушки с номером задачи); ассистента (S7, B8). Статусы задач — [docs/tasks.md](docs/tasks.md).

## Быстрый старт
Нужны Git, Docker Desktop и Node из [.nvmrc](.nvmrc) (24 LTS). На Windows работай внутри WSL2.

```sh
cp .env.example .env
docker compose up -d --build          # db + backend → http://localhost:8000/api/health

cd frontend && npm ci && npm run dev  # кабинет → http://localhost:5173
```

Фронт без бэка, на моке контракта: `docker compose --profile mock up -d mock`, затем `npm run dev:mock` в frontend/.

## Проверки
| Что | Команда |
|---|---|
| Тесты бэка | `docker compose run --rm backend pytest` |
| Линт бэка | `docker compose run --rm backend sh -c "ruff check --fix . && ruff format ."` |
| Фронт (в frontend/) | `npm run lint && npm run typecheck && npm test` |
| Клиент API из контракта (в frontend/) | `npm run gen:api` |
| e2e (в e2e/, бэк должен быть поднят) | `npm ci && npx playwright install chromium && npx playwright test` |

CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) гоняет то же самое, а ещё сверяет сгенерированный клиент с контрактом, запускает gitleaks и `manage.py check --deploy`. Локальные хуки (необязательно): `pipx install pre-commit && pre-commit install`.

## Демо-учётки
При `DEMO_MODE=1` (по умолчанию в docker-compose) бэкенд при каждом старте досоздаёт каталог продуктов и демо-персоны (`manage.py seed_demo`; существующее не трогает). Вход — кнопкой «Войти» напротив персоны на странице `/login` (`POST /api/demo/login`). **Паролей у демо-учёток нет** — войти по логину и паролю за них нельзя. Сюжеты — [docs/demo.md](docs/demo.md), шаги и ожидаемые исходы — [docs/test-scenarios.md](docs/test-scenarios.md).

| Сценарий | Код персоны | Логин | Компания (всё «демо») | Роль |
|---|---|---|---|---|
| 1 | `coffee_shop` | `demo_coffee_shop` | ИП, кофейня «Зерно и пар» — овердрафт | подписант |
| 2 | `retail_supplier` | `demo_retail_supplier` | ООО «Северный поставщик» — факторинг | подписант |
| 3 | `garden_store` | `demo_garden_store` | ИП, садовый центр «Зелёный двор» — контроффер | подписант |
| 4 | `furniture_maker` | `demo_furniture_maker` | ООО «Дубрава Мебель» — ручное рассмотрение | подписант |
| 4 | `accountant` | `demo_accountant` | ООО «Дубрава Мебель» — главный бухгалтер | готовит заявку (preparer) |
| 5 | `dependent_supplier` | `demo_dependent_supplier` | ООО «Опора Снаб» — отказ с советами | подписант |
| 6 | `liquidating_company` | `demo_liquidating_company` | ООО «Вектор Сервис» — компания в ликвидации | подписант |
| 7 | `bki_outage` | `demo_bki_outage` | ИП, кофейня «Северный ветер» — сбой БКИ | подписант |
| 8 | `equipment_no_collateral` | `demo_equipment_no_collateral` | ООО «Ковка и Фреза» — лизинг вместо инвест-кредита | подписант |
| — | `bank` | `demo_bank` | сотрудник банка | `/bank` |

Исходы сценариев 1–6 и 8 конвейер выдаёт сам после отправки. Сценарий 7 (сбой БКИ): сотрудник банка включает сбой `PUT /api/demo/failures` с `"bki": true` (экран демо-панели — B7), затем персона `bki_outage` отправляет заявку. Своя учётка — через `/register` (без почты); компанию к ней пока можно подключить только через API (`POST /api/company` по ИНН из синтетического реестра) — экран профиля компании ещё заглушка (C3).

## Данные и секреты
- В `.env` — только локальные значения; в репозиторий попадает лишь [.env.example](.env.example) с заглушками.
- Данных от организаторов нет: все компании, выписки, реестры и кредитные истории — синтетика единого детерминированного генератора ([docs/data-spec.md](docs/data-spec.md)), помечены «демо». Внешние источники (ЕГРЮЛ, БКИ, «Прозрачный бизнес», счёт) — симуляторы.
- ИИ-ассистент по умолчанию работает на `LLM_PROVIDER=mock` — без сети и ключа.
